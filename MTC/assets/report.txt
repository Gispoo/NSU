Постановка задачи
Цель: разработать парсер оператора INPUT языка BASIC, включая грамматику, выбор метода анализа, реализацию с GUI и тесты.

Примеры языковых цепочек
(см. меню Справка / Примеры)

Язык и грамматика (тип по Хомскому)
Токены: INPUT, STRING, ID, ',', ';', EOL, EOF
Грамматика (стартовый символ Z):
  Z       → INPUT H VarList EOL
  H       → STRING ',' | STRING ';' | ε
  VarList → Var T
  T       → ',' Var T | ε
  Var     → ID
Классификация: контекстно-свободная грамматика (Тип-2 по Хомскому).

FIRST/FOLLOW (доказательство LL(1))
FIRST(Z) = { INPUT }
FIRST(H) = { STRING, ε }
FIRST(VarList) = { ID }
FIRST(T) = { ',', ε }
FIRST(Var) = { ID }
FOLLOW(Z) = { $ }
FOLLOW(H) = { ID }
FOLLOW(VarList) = { EOL }
FOLLOW(T) = { EOL }
FOLLOW(Var) = { ',', EOL }
Вывод: конфликтов FIRST/FOLLOW нет; для H требуется одноксимвольный lookahead (','|';'). Грамматика LL(1).

Выбор метода анализа
Метод: нисходящий разбор LL(1), рекурсивный спуск. Обоснование: грамматика без левой рекурсии; множества FIRST/FOLLOW не конфликтуют; достаточно 1 символ заглядывания; реализация компактная; удобно для диагностики и нейтрализации ошибок.

Нейтрализация ошибок
Паник-режим: при ошибке пропускаем токены до точки синхронизации (ID/EOL/EOF), выдаём диагностическое сообщение с позицией.

Алгоритм синтаксического анализа
Лексер преобразует исходный текст в токены; парсер реализует функции parse_Z, parse_H, parse_VarList, parse_T, parse_Var согласно правилам грамматики, производит диагностику ошибок и попытки восстановления.

Реализация парсера
Реализация приведена в данном приложении (Python + Tkinter), код лексера и парсера включён.
